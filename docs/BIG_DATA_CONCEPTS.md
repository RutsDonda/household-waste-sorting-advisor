## 1. Executive Architecture Summary

Municipal solid waste management in modern smart cities generates millions of data points daily—from smart residential bins, citizen mobile apps, sorting facilities, and collection trucks. This project models and implements an end-to-end Big Data System (BDS) that combines **Deep Learning Computer Vision** at ingestion with **NoSQL Big Data Storage (MongoDB)** and **Distributed Batch Analytics (Apache Spark / PySpark)**.

## 2. Mapping to the "5 V's of Big Data"

| Big Data "V" | Municipal Waste System Context | Implementation in this Project |
| :--- | :--- | :--- |
| **Volume** | Millions of daily waste events generated by thousands of residential apartments and commercial buildings. | Partitioned MongoDB collections and PySpark batch pipeline designed for parallel DataFrame processing across clusters. |
| **Velocity** | Citizens and IoT sorting bins submit images and disposal queries simultaneously around the clock. | Asynchronous, non-blocking REST API endpoints powered by FastAPI (`async/await`) and asynchronous Motor MongoDB driver. |
| **Variety** | Multi-modal data: Unstructured binary image payloads, semi-structured JSON inference metadata, geographical tags, and time-series telemetry. | NoSQL schema-flexible document store (BSON/JSON) in MongoDB storing diverse attributes without rigid relational table migrations. |
| **Veracity** | Real-world image noise, occlusion, varying lighting, and ambiguous items (e.g., contaminated plastic vs. clean paper). | AI confidence scores, configurable low-confidence thresholds (<0.70), manual verification fallback, and model confidence distribution auditing. |
| **Value** | Transforming raw disposal records into actionable insights: diversion rates, household segregation scores, municipal collection optimization. | Analytics dashboard, household waste stewardship scoring algorithm, recycling percentage tracking, and municipal trend forecasts. |

## 3. Core Big Data Concepts Demonstrated

### 3.1 Large-Scale Data Collection
- **High-Throughput Ingestion:** Implemented via FastAPI REST APIs (`POST /api/predict`). The server uses non-blocking asynchronous event loops to accept concurrent file uploads.
- **Payload Validation & Sanitization:** Enforces strict mime-type verification (`.jpg`, `.png`, `.webp`) and payload size limits (<10MB) to protect ingestion pipelines against buffer overflow and DOS vectors.

### 3.2 Scalable Storage Layer (MongoDB)
- **Document Model:** Records are stored in polymorphic BSON documents. Each record encapsulates the raw image path, item label, category, confidence vector, household identifier, and timestamp.
- **Indexing Strategy:**
  - `{"timestamp": -1}`: Enables ultra-fast time-series slicing for daily/weekly/monthly trends.
  - `{"category": 1}`: Accelerates category aggregation and filtering.
  - `{"household_id": 1}`: Optimizes household profile lookups and segregation score calculation.
  - `{"confidence": -1}`: Enables fast filtering for low-confidence audit reports.

### 3.3 Data Preprocessing & Cleaning
- **Missing Value & Outlier Handling:** Normalizes corrupted or null timestamps to current server UTC; validates category strings against registered taxonomy.
- **Feature Extraction:** Image tensors are resized to standard dimensions ($224 \times 224 \times 3$) and normalized using ImageNet channel means $(\mu = [0.485, 0.456, 0.406], \sigma = [0.229, 0.224, 0.225])$.

### 3.4 Batch Processing Pipeline (Apache Spark / PySpark)
- **Parallel DataFrame Computations:** The batch processing module (`analytics/pyspark_pipeline.py`) loads records into a Spark DataFrame and distributes partitions across worker cores.
- **MapReduce Equivalents:**
  - **Map Phase:** Extracts `(category, 1)` and `(date, count)` pairs.
  - **Shuffle & Sort:** Partitions records by key across executor nodes.
  - **Reduce Phase:** Aggregates totals, averages confidence, and calculates standard deviations.
- **Window Functions:** Computes rank and frequency of waste items within household partitions without collapsing the underlying dataset.
- **Modular Fallback:** A parallel high-performance Pandas/NumPy engine (`analytics/pandas_fallback.py`) guarantees 100% testability on environments where Spark clusters or Windows winutils are not installed.

### 3.5 Analytical Aggregations & Formulas

#### A. Municipal Recycling & Diversion Rate
The municipal diversion rate measures the percentage of waste diverted from landfills into recycling or composting streams:
$$\text{Diversion Rate (\%)} = \left( \frac{N_{\text{recyclable}} + N_{\text{organic}}}{N_{\text{total}}} \right) \times 100$$
Where $N_{\text{recyclable}} = N_{\text{plastic}} + N_{\text{paper}} + N_{\text{glass}} + N_{\text{metal}}$.

#### B. Household Waste Stewardship Score (Project Metric)
To incentivize citizens, the system calculates a normalized score from $0$ to $100$:
$$\text{Score} = \min\left(100, \left( \frac{N_{\text{recyclable}} + N_{\text{organic}}}{N_{\text{total}}} \right) \times 85 + \text{Bonus}_{\text{hazardous}}\right)$$
*Note: This metric is explicitly presented as a project-defined demonstration index rather than an official regulatory standard.*

## 4. Artificial Intelligence & Edge Classification

### 4.1 MobileNetV2 Architecture
- **Inverted Residual Blocks & Depthwise Separable Convolutions:** Dramatically reduces floating point operations (FLOPs) compared to standard CNNs (VGG16/ResNet50), making it ideal for edge sorting stations and mobile applications.
- **Transfer Learning:** Pretrained ImageNet weights are frozen in initial layers to retain edge and texture filters, while the custom classification head is fine-tuned on the 8 municipal waste classes.
- **Evaluation Rigor:** Evaluated with Accuracy, Macro/Weighted Precision, Recall, F1 Score, and an $8 \times 8$ Confusion Matrix.

## 5. College Viva Voce Questions & Model Answers

### Q1: Why use MongoDB instead of a traditional relational database (MySQL/PostgreSQL)?
> **Answer:** Household waste data exhibits high schema variability (e.g., some records have bounding boxes, multi-class probabilities, sensor telemetry, or manual feedback notes). MongoDB's flexible BSON document model easily accommodates these evolving fields without database schema locks or costly table migrations. Furthermore, MongoDB natively shards across clusters for horizontal scalability as data volume scales into millions of records.

### Q2: What is the difference between Batch Processing and Stream Processing in this system?
> **Answer:** Stream processing occurs at ingestion when an individual citizen uploads an image and receives an immediate real-time AI classification ($<500\text{ms}$). Batch processing (implemented via our PySpark pipeline) aggregates hundreds of thousands of historical records periodically (e.g., hourly or daily) to identify macro trends, compute household scores, and generate municipal waste volume forecasts that do not require sub-second latency.

### Q3: How does PySpark execute the groupBy aggregation under the hood?
> **Answer:** PySpark executes `groupBy()` using an initial map-side partial aggregation (`Aggregator` or `HashAggregate`), followed by an exchange (shuffle) phase where keys are hashed and transferred across network partitions to reducer tasks, which compute the final aggregate value. This minimizes network overhead compared to sending raw records directly across nodes.

### Q4: Why is transfer learning with MobileNetV2 preferred over training a CNN from scratch?
> **Answer:** Training a deep convolutional neural network from scratch requires hundreds of thousands of annotated waste images and weeks of GPU compute. MobileNetV2 transfer learning leverages low-level visual features (edges, contours, color gradients) pre-learned on 1.4 million ImageNet images, requiring only hundreds of domain-specific waste images to achieve $>90\%$ accuracy while keeping model size lightweight ($\sim 14\text{MB}$).
